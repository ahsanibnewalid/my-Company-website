# Axiom Labs — one website, one owner dashboard

This repository deploys a **single Next.js 15 application** to one Render web service. The public website, server-side API, and private owner dashboard are all included. PostgreSQL stores project inquiries, career applications, projects, and website settings.

No Django service, public account signup, Resend integration, staff/client portals, or authenticator enrollment is required.

## What works

- Public homepage and contact/career forms at `/`.
- One predefined administrator login at `/admin` (email and password only).
- Dashboard at `/admin/dashboard` with message status and deletion, project management, and website settings.
- Published featured projects and editable tagline/founder/contact details on the homepage.
- Private password verification with scrypt, signed 12-hour HttpOnly session cookie, origin checks and parameterized SQL.
- No default admin credentials, no email forwarding. Forms only show success after a database insert.

## Local development

Requires Node.js 22+ and a PostgreSQL database.

```bash
npm install
npm run admin:hash
cp .env.example .env.local
```

The `admin:hash` command securely prompts you for a **new password of at least 14 characters** without displaying it. It prints the `ADMIN_PASSWORD_HASH` and a random `SESSION_SECRET`. Copy both privately into `.env.local` with:

| Variable | Description |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string (TLS for managed production databases). |
| `ADMIN_EMAIL` | Exactly one approved owner email. |
| `ADMIN_PASSWORD_HASH` | The scrypt result from `npm run admin:hash`. Do **not** use a plaintext password. |
| `SESSION_SECRET` | Random secret generated by the same command. |

Then run `npm run dev` and open `http://localhost:3000/admin`. The database tables are initialized automatically when an API endpoint first needs them; the configured database user must have `CREATE TABLE` privilege.

## Render Free deployment

The root `render.yaml` defines **one** web service. In Render → your Axiom Labs web service → **Environment**, set all four variables above as private environment variables, then redeploy. Do not prefix them with `NEXT_PUBLIC_`. The database is a **separate managed PostgreSQL database**, not a second application server.

**Important:** Render's Free web service has an ephemeral filesystem. Do not use SQLite or file storage there. Render Free PostgreSQL instances expire after 30 days and are not suitable for durable customer records. For real inquiries, use PostgreSQL that offers continued storage and backups. Confirm the provider's SSL connection-string requirements.

After deployment:

1. Open `/admin` and sign in with `ADMIN_EMAIL` and the **original password you chose**, not the hash.
2. Open the dashboard and save website settings.
3. Submit a real test inquiry from the homepage and verify it appears under Messages.
4. Add a featured project and verify it appears on the public homepage.

Changing `ADMIN_PASSWORD_HASH` invalidates existing sessions. To recover access, generate a new hash and update the Render environment; there is no public password-reset workflow.

## Before serving real customers

Confirm the company's legal details and privacy contact; choose and publish a data retention policy; enable managed database backups, monitoring and production-grade distributed rate limiting. Basic application-level throttles are process-local and reset when the free instance restarts. There is no built-in outbound email notification, so review the dashboard regularly.
